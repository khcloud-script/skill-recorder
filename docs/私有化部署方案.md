## 1. 方案总览

Skill Recorder 是一个 **Electron 桌面客户端**：屏幕/窗口/终端/语音的采集、
敏感信息脱敏（secretlint + OCR）全部在**用户本机**完成；唯一需要"出网"的环节
是把脱敏后的录屏摘要（时间线/事件/截图帧/语音转写）发送给大模型做意图分析，
生成 SKILL.md / automation。

原版通过 GitHub Copilot CLI 完成分析（强依赖 GitHub 云服务）。
本仓库新增了 **OpenAI 兼容私有后端**（`electron/llm/`），只需配置几个
环境变量，即可把分析请求切换到**任意 OpenAI 兼容接口**：

```text
┌───────────────────────────────┐        ┌──────────────────────────────┐
│     员工终端 (Windows/macOS)   │        │        内网推理服务            │
│                               │        │                              │
│  Skill Recorder（桌面客户端）   │ HTTPS  │  vLLM / Ollama / Xinference  │
│  ├─ 录屏 / 事件 / 终端采集      │───────▶│  (OpenAI 兼容 /v1 接口)        │
│  ├─ Whisper 本地语音转写        │        │  Qwen2.5-VL / GLM-4V / ...   │
│  └─ 机密信息本地脱敏（OCR 打码） │        │                              │
└───────────────────────────────┘        └──────────────────────────────┘
           全程数据不出内网，无需 GitHub 账号 / Copilot 订阅
```

- **最简部署**：一台带 GPU 的服务器（或员工本机）跑 Ollama/vLLM + 一个支持
  工具调用的视觉模型，客户端配 3 个环境变量。10 分钟完成。
- **完整部署**：GPU 集群 + vLLM 推理服务 +（可选）LiteLLM 统一网关 +
  MinIO 对象存储 + 内部制品库分发的客户端安装包。

> 与 `docs/skill-recorder_copilot分析.md` 中的设想不同：本改造**不需要**部署
> 独立的服务端 Whisper/PaddleOCR —— 客户端已内置本地 Whisper
> (`@huggingface/transformers`) 与本地 OCR 打码。第三方语音/OCR 服务只在你
> 希望**替换内置实现**时才需要，属可选项。

## 2. 工作原理与代码改造说明

### 2.1 请求链路

原版：`Electron 主进程 → @github/copilot-sdk → copilot CLI（子进程）→ GitHub 云服务`。
分析 Agent 使用**自定义工具调用**（`get_timeline`、`get_events`、`get_frames`、
`submit_analysis` 等），CLI 负责多轮工具循环。

改造后增加了一个后端抽象层（仅新增了 `electron/llm/`，不侵入原有流程）：

```text
describer / skillbuilder / automationbuilder
        │
        ▼
  electron/llm/factory.ts   ←── 读 electron/llm/config.ts 的配置
        │
        ├── 未配置私有 LLM ──→ CopilotClient（原版行为，未改动）
        │
        └── 已配置私有 LLM ──→ OpenAIAgentClient（新增）
                                   │  POST {baseUrl}/chat/completions
                                   │  tools: 应用内的沙箱工具（JSON Schema）
                                   │  多轮 tool_calls 循环，图像以 data-url 内联
                                   ▼
                          任意 OpenAI 兼容推理服务
```

要点：

- **工具循环在客户端内完成**：调私有模型时，copilot CLI 完全不参与，
  也**不需要 GitHub 登录**；UI 中的"登录 Copilot"流程仅在默认模式下出现。
- **沙箱不变**：私有后端只允许调用应用显式传入的工具
  （读取本录制会话的数据），没有任何 shell/文件写权限。
- **视觉模型按需**：`get_frames` 返回的截图仅在配置了视觉模型时发送；
  文本-only 模型会自动跳过图片并附提示（分析精度略降，功能不受影响）。
- **会话/并发控制**逻辑（每个录制一个会话、空闲回收、超时、取消）保持不变。

### 2.2 变更文件清单

| 文件 | 变更 |
| --- | --- |
| `electron/llm/config.ts` | 新增：环境变量/配置文件解析，内置 9 个厂商预设 |
| `electron/llm/types.ts` | 新增：`AgentClient`/`AgentSession` 后端抽象接口 |
| `electron/llm/openai-client.ts` | 新增：OpenAI 兼容 agent client（工具循环/视觉/超时/取消） |
| `electron/llm/factory.ts` | 新增：后端工厂，一键切换 Copilot / 私有 LLM |
| `electron/describer/describer.ts` | 改为经工厂获取后端；私有模式自动选视觉模型 |
| `electron/builders/agent-builder.ts` | 改为经工厂获取后端 |
| `electron/skillbuilder/builder.ts`、`electron/automationbuilder/builder.ts` | 类型切到抽象接口 |
| `electron/doctor.ts` | 环境自检显示当前后端（私有模式显示「厂商 · 端点 · 模型」） |

Copilot 登录相关代码（`copilot-signin*.ts`）原样保留：未配置私有 LLM 时行为
与上游完全一致。

## 3. 模型选型指南

分析 Agent 对模型的硬性要求：

1. **支持工具调用（function calling）** —— 必需；
2. **长上下文**（建议 ≥ 32K，事件流可能很大）；
3. **视觉能力**（VLM）—— 可选但推荐，用于"看"屏幕截图。

推荐模型（均可私有化部署、OpenAI 兼容输出）：

| 场景 | 模型 | 显存（FP16/INT8） | 说明 |
| --- | --- | --- | --- |
| 首选（视觉+工具） | Qwen2.5-VL-32B-Instruct | ~70GB / ~35GB | 视觉强、工具调用稳定、中文好 |
| 高性价比 | Qwen2.5-VL-7B-Instruct | ~18GB / ~10GB | 单卡 RTX 4090/A10 可跑 |
| 大上下文旗舰 | GLM-4V-Flash(云端) / GLM-4.1V-9B(自部署) | ~24GB | 智谱系，支持工具调用 |
| 纯文本降级 | DeepSeek-V3 / Qwen2.5-72B-Instruct | 依规模 | 无法看截图，仅事件流分析 |
| 轻量验证 | Qwen2.5-VL-7B + Ollama | ~10GB | 开发/PoC 首选 |

> 不建议在默认门禁下使用：Llama 3.x Vision（工具调用格式兼容性需自行验证）、
> 纯代码模型、不支持 function calling 的老模型。
> 务必先用 `deploy/scripts/check-llm.sh` 做[连通性自检](#附录)。

## 4. 方案 A：最简部署

适用于：PoC、小团队（≤ 50 人）、或已有推理服务只想"接上线"。

**目标**：一台服务器跑模型，N 台终端装客户端，客户端指向服务器即可。

### 4.1 服务端（任选其一）

#### 选项 1：Ollama（最简单，推荐起步）

```bash
# GPU 服务器（或员工本机，需 ≥ 24GB 显存）
curl -fsSL https://ollama.com/install.sh | sh

# 拉取支持工具调用的视觉模型
ollama pull qwen2.5vl:32b        # 显存紧张可换 qwen2.5vl:7b

# 对外提供服务（默认只监听 127.0.0.1）
sudo systemctl edit ollama
# [Service]
# Environment="OLLAMA_HOST=0.0.0.0:11434"
sudo systemctl restart ollama
```

Ollama 自带 OpenAI 兼容接口：`http://<服务器IP>:11434/v1`。

> **内网无外网**：将能上网机器上 `~/.ollama/models` 目录整体拷贝到内网
> (`ollama list` 可核对)，或使用 `ollama cp` / 私有 registry 分发。

#### 选项 2：vLLM（生产性能）

```bash
# 2×A100 / 4×A10 均可
docker run -d --name vllm --gpus all \
  -p 8000:8000 \
  -v /data/models:/models \
  vllm/vllm-openai:latest \
  --model /models/Qwen2.5-VL-32B-Instruct \
  --served-model-name qwen-vl \
  --max-model-len 32768 \
  --enable-auto-tool-choice \
  --tool-call-parser hermes
```

关键点（**缺一不可**）：

- `--enable-auto-tool-choice --tool-call-parser hermes`：开启工具调用协议
  （Qwen2.5 系列用 `hermes` parser；GLM 用 `--tool-call-parser glm`）。
- 模型权重提前在内网准备好（HuggingFace/ModelScope 下载后拷贝，
  或企业模型仓库镜像）。

### 4.2 客户端配置（3 个环境变量）

以 Ollama 为例（vLLM 仅换 provider/base url）：

**Linux / macOS**：

```bash
export SKILL_RECORDER_LLM_PROVIDER=ollama
export SKILL_RECORDER_LLM_BASE_URL=http://<服务器IP>:11434/v1
export SKILL_RECORDER_LLM_MODEL=qwen2.5vl:32b

skill-recorder          # 或开发态 npm run dev
```

**Windows（PowerShell）**：

```powershell
$env:SKILL_RECORDER_LLM_PROVIDER = "ollama"
$env:SKILL_RECORDER_LLM_BASE_URL = "http://<服务器IP>:11434/v1"
$env:SKILL_RECORDER_LLM_MODEL    = "qwen2.5vl:32b"
.\skill-recorder.exe
```

> 无需 API Key 时 `SKILL_RECORDER_LLM_API_KEY` 可省略（本机会假请求头省略
> Authorization）。若网关要求鉴权（LiteLLM/One-API），设置
> `SKILL_RECORDER_LLM_API_KEY=sk-...` 即可。

为方便分发，仓库提供了启动包装脚本（见 [附录](#9-附录部署脚本清单)）：

```bash
cp deploy/minimal/skill-recorder.env.example ~/.config/skill-recorder/llm.env
# 编辑你的端点与模型后：
deploy/minimal/run-private.sh
```

也支持**配置文件**（适合不便于设置环境变量的终端统一管控），
路径 `~/.skill-recorder/llm.config.json`（参考
`deploy/minimal/llm.config.json.example`），环境变量优先级高于配置文件。

### 4.3 验证

1. 服务端：`deploy/scripts/check-llm.sh http://<服务器IP>:11434/v1 qwen2.5vl:32b`
   应输出工具调用测试通过。
2. 客户端：打开 Skill Recorder → 短录制一段（10s）→ Analyze；
   进度条正常走完且不出"sign in"提示即成功。
3. 应用日志（doctor）会显示 `vLLM 自建推理集群 · http://... · model xxx`。

### 4.4 最简方案清单（总结）

| 组件 | 数量 | 规格 |
| --- | --- | --- |
| GPU 服务器 | 1 | 1×RTX 4090/A10（24GB）起 |
| 客户端 | N | 无 GPU 要求 |
| 依赖 | Ollama + 1 个模型权重 | 净资产 ~23GB |

## 5. 方案 B：完整部署

适用于：≥ 100 人、多模型并存、统一鉴权/审计、高可用。

```text
              员工终端（客户端）
                    │ HTTPS/内部证书
                    ▼
        ┌──────────────────────────┐
        │  内网网关 (LiteLLM Proxy) │──▶ 审计日志 / 配额 / 鉴权
        └──────────┬─────┬────────┘
                   │     │
        ┌──────────▼┐ ┌──▼─────────┐
        │ vLLM-视觉 │ │ vLLM-文本   │  ← 多模型并存
        │ qwen-vl   │ │ deepseek-v3│
        └───────────┘ └────────────┘
                   ▲
        ┌──────────┴─────────────┐
        │ GPU 集群 (K8s/Volcano)  │
        └────────────────────────┘
        ┌────────────────────────┐
        │ MinIO（模型权重/制品库） │
        │ Harbor（镜像仓库）      │
        │ Verdaccio（npm 私有源） │
        └────────────────────────┘
```

### 5.1 推理服务（vLLM 生产部署）

完整 compose 文件见 `deploy/full/docker-compose.yml`，核心服务：

```yaml
# 节选
vllm-vision:
  image: vllm/vllm-openai:v0.9.0
  command:
    - --model=/models/Qwen2.5-VL-32B-Instruct
    - --served-model-name=qwen-vl
    - --max-model-len=32768
    - --enable-auto-tool-choice
    - --tool-call-parser=hermes
    - --tensor-parallel-size=2
  deploy:
    resources:
      reservations:
        devices:
          - driver: nvidia
            count: 2
            capabilities: [gpu]
  ports: ["8000:8000"]

vllm-text:
  image: vllm/vllm-openai:v0.9.0
  command:
    - --model=/models/DeepSeek-V3
    - --served-model-name=deepseek-v3
    - --enable-auto-tool-choice
    - --tool-call-parser=hermes
    - --tensor-parallel-size=4
  # 同上 GPU 配置 ...
  ports: ["8001:8000"]
```

**单机 GPU 部署多模型耗尽显存时的替代**：把文本/视觉合并为一张卡上的
`Qwen2.5-VL-7B + CPU offload`，或分别两台机器。

### 5.2 统一网关（可选，推荐）

LiteLLM 把多个后端收敛为一个入口，并提供企业必需的能力：API Key、
模型别名切换、限流、调用审计、fallback 路由。配置示例
（`deploy/full/litellm-config.yaml`）：

```yaml
model_list:
  - model_name: qwen-vl
    litellm_params:
      model: openai/qwen-vl
      api_base: http://vllm-vision:8000/v1
  - model_name: deepseek-v3
    litellm_params:
      model: openai/deepseek-v3
      api_base: http://vllm-text:8000/v1

general_settings:
  master_key: sk-skill-recorder-master
```

客户端只需固定指向网关 `http://litellm.intra:4000/v1`、模型名填别名，
**热切换后端模型不需要触达任何终端**。

### 5.3 客户端规模化分发

1. 参照《[离线编译与打包](./离线编译与打包.md)》在企业制品库里完成
   `npm ci` + `npm run dist`，产出 Windows/macOS 安装包；
2. 通过 MDM / Ansible / SCCM 分发安装包 + 统一的
   `llm.config.json`（用户目录）或环境变量策略（Windows 组策略 /
   macOS MDM profile）；
3. 三个环境变量即可（`PROVIDER=custom`、`BASE_URL`、`API_KEY`），
   模型名由网关别名决定，模型升级对客户端完全透明。

### 5.4 资源规划参考

| 规模 | 并发会话 | GPU | 推荐模型 |
| --- | --- | --- | --- |
| ≤ 50 人 | ≤ 5 | 1×A10 (24GB) | Qwen2.5-VL-7B |
| 100~500 人 | ≤ 30 | 2×A800 | Qwen2.5-VL-32B |
| 1000+ | ≤ 100 | 4×A800 + K8s | 32B 视觉 + DeepSeek 文本分层 |

> 分析一次录制 ≈ 5–30 次 LLM 调用、20K–100K tokens；单 QPS 峰值不高，
> 主要瓶颈是**显存**与**长上下文并发**。

### 5.5 对象存储与审计（可选增强）

原版客户端不做服务端上传，录制产物保存在终端本地
（`SKILL_RECORDER_SESSIONS_DIR` 可统一改到企业盘）。若需集中归档：

- 客户端侧用计划任务同步 `sessions/` → MinIO（S3 兼容）；
- SKILL.md 产出目录 `~/.copilot/skills`（或
  `SKILL_RECORDER_SKILLS_DIR`）建议对接内网 GitLab/Gitea 做版本管理
  （Skills 即 SOP，需评审/回滚时收益显著）。

## 6. 模型切换与配置参考

### 6.1 环境变量完整参考

| 变量 | 必填 | 说明 |
| --- | --- | --- |
| `SKILL_RECORDER_LLM_PROVIDER` | 否* | 预设 id：`vllm` / `ollama` / `xinference` / `deepseek` / `qwen` / `zhipu` / `moonshot` / `azure` / `custom` |
| `SKILL_RECORDER_LLM_BASE_URL` | 否* | OpenAI 兼容端点（含 `/v1`）。`custom` 时必填 |
| `SKILL_RECORDER_LLM_API_KEY` | 按需 | Bearer Token；无鉴权时可留空 |
| `SKILL_RECORDER_LLM_MODEL` | 是** | 分析用主模型（preset 有默认时可省） |
| `SKILL_RECORDER_LLM_VISION_MODEL` | 否 | 视觉模型，未设则回退 `MODEL` |
| `SKILL_RECORDER_LLM_VISION` | 否 | `1`/`0` 强制开/关图像输入（默认按预设） |
| `SKILL_RECORDER_LLM_MAX_TOKENS` | 否 | 单次响应上限，默认 8192 |
| `SKILL_RECORDER_MODEL` | 否 | 旧的强指定模型变量，两种模式均生效 |

\* 以上任一（或配置文件存在）即启用私有模式；都不配置则保持 Copilot 行为。

### 6.2 常见厂商一行切换

```bash
# vLLM 自建
SKILL_RECORDER_LLM_PROVIDER=vllm SKILL_RECORDER_LLM_BASE_URL=http://gpu01:8000/v1 SKILL_RECORDER_LLM_MODEL=qwen-vl

# DeepSeek 官方 API
SKILL_RECORDER_LLM_PROVIDER=deepseek SKILL_RECORDER_LLM_API_KEY=sk-...

# 智谱 GLM
SKILL_RECORDER_LLM_PROVIDER=zhipu SKILL_RECORDER_LLM_API_KEY=xxx SKILL_RECORDER_LLM_MODEL=glm-4-plus

# Moonshot
SKILL_RECORDER_LLM_PROVIDER=moonshot SKILL_RECORDER_LLM_API_KEY=sk-...

# 任意兼容网关（One-API / LiteLLM / FastChat...）
SKILL_RECORDER_LLM_PROVIDER=custom SKILL_RECORDER_LLM_BASE_URL=https://llm.intra.company/v1 SKILL_RECORDER_LLM_API_KEY=sk-... SKILL_RECORDER_LLM_MODEL=qwen-vl
```

> 切换模型 = 改一行环境变量（或网关别名），无需重启客户端以外的一切。

### 6.3 配置文件方式（终端统一管控推荐）

`~/.skill-recorder/llm.config.json`（参考 `deploy/minimal/llm.config.json.example`）：

```json
{
  "provider": "custom",
  "baseUrl": "http://litellm.intra.company:4000/v1",
  "apiKey": "sk-...",
  "model": "qwen-vl",
  "vision": true,
  "maxTokens": 8192
}
```

优先级：**环境变量 > 配置文件 > 预设默认值**。密钥亦可由企业 EDR/密管
系统在登录时注入环境变量，不落盘。

## 7. 安全设计

1. **敏感信息本地脱敏**（原版能力，私有模式同样生效）：
   发送给模型前对事件流中的密钥/PII 做掩码，截图帧 OCR 打码。
   私有模式下这些**依然在内网**流转，风险面进一步缩小。
2. **传输**：建议网关前自签/内部 CA 的 HTTPS 反向代理（Nginx），
   API Key 走 Authorization 头。
3. **存储**：录制文件仅在本机；`SKILL_RECORDER_SESSIONS_DIR` 可挂到加密盘。
4. **模型侧权限**：推理网关开启按 API Key 审计并无状态化，不落地请求体；
   审计需求强则落盘但设置短保留期。
5. **最小工具面**：私有后端仅暴露应用注入的只读工具，模型无法在终端执行命令。
6. **禁止事项**：不要在公网部署推理服务后直接配公网 IP —— 录屏内容可能
   含机密，一律走内网/VPN。

## 8. 常见问题（FAQ）

**Q1：仍然让我登录 GitHub Copilot？**
说明环境变量没有生效（从文件管理器双击启动 often 不加载 shell rc）。
用包装脚本 `deploy/minimal/run-private.sh`，或使用 `~/.skill-recorder/llm.config.json` 配置文件。

**Q2：Analyze 时立刻报 `request failed (400)` / `tool_calls not supported`？**
模型或服务未开启工具调用：vLLM 必须加 `--enable-auto-tool-choice
--tool-call-parser hermes`；Ollama 需 ≥ 0.6 且模型支持 tools。先用
`deploy/scripts/check-llm.sh` 自检。

**Q3：分析结果很糙/看不到截图？**
仅在配置了视觉能力（`SKILL_RECORDER_LLM_VISION=1` 或视觉预设）且模型确实
支持图像输入时，截图才会送出。纯文本模型（如 deepseek-chat）会收到
"images omitted"提示，属预期降级。

**Q4：超时错误 `Turn timed out`？**
大模型生成慢或上下文超长。缩短录制、降低 `get_frames` 采样，或适当调低
`SKILL_RECORDER_LLM_MAX_TOKENS`（生成更紧凑）。

**Q5：多台终端能否共用同一个模型端点？**
可以，服务端就是普通的 web 服务；并发容量由 GPU 集群决定。

**Q6：已有 GitHub Copilot 订阅，能用官方模式吗？两种模式如何切换？**
不设任何 `SKILL_RECORDER_LLM_*` 变量即是官方模式，与上游完全一致；
想切回官方模式删掉这些变量（或配置文件）即可，无需改代码。

**Q7：如何在内网完成编译？**
见《[离线编译与打包](./离线编译与打包.md）》。
