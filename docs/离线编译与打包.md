# 离线编译与打包（内网 / 无外网环境）

> 本文档适用于：Skill Recorder 需要在**无外网或访问受限**的环境中完成
> 编译、打包与终端分发。配套脚本见 `deploy/scripts/`。

## 1. 一句话流程

```text
有网开发机 ──▶ 收集依赖包（npm tarballs / Electron 二进制 / 模型权重）
        │       刻盘 / 制品库中转
        ▼
内网构建机 ──▶ npm ci（走私有镜像）→ npm run build → npm run dist
        │
        ▼
内网分发系统 ──▶ 终端安装包 + llm.config.json（或环境变量）
```

## 2. 依赖清单与镜像方案

| 依赖 | 默认来源 | 内网替代 |
| --- | --- | --- |
| npm 依赖 | npmjs.org | Verdaccio / Nexus npm 代理，或离线 tar 包 |
| Electron 二进制 | github.com/releases | `ELECTRON_MIRROR` 指向内网镜像 |
| electron-builder 辅助工具 | github.com | `ELECTRON_BUILDER_BINARIES_MIRROR` |
| HuggingFace 语音模型（语音转写） | huggingface.co | `HF_ENDPOINT` 内网镜像，或预置 `SKILL_RECORDER_MODELS_DIR` |
| Copilot CLI（可选） | npm 包已内置私有模式不需要 | — |

最关键的两个环境变量：

```bash
# Electron 主二进制镜像（目录布局需与官方 mirror 一致）
export ELECTRON_MIRROR="https://npm-mirror.intra.company/mirrors/electron/"
# electron-builder 下载的辅助工具（nsis 等）
export ELECTRON_BUILDER_BINARIES_MIRROR="https://npm-mirror.intra.company/mirrors/electron-builder-binaries/"
# npm registry
export npm_config_registry="https://npm-mirror.intra.company/repository/npm/"
# HuggingFace 端点（skill recorder 的语音/敏感 OCR 模型）
export HF_ENDPOINT="https://hf-mirror.intra.company"     # 或 hf-mirror.com 公网镜像
```

## 3. 离线 npm 依赖（无 registry 可用时）

在**有网机器**上：

```bash
# 1) 检出完全相同的代码版本
git checkout <commit>

# 2) 安装依赖（保证 package-lock.json 一致，会写入缓存）
npm ci --no-audit --no-fund

# 3) 将 npm 缓存打包带走（后续内网从这个缓存恢复）
tar czf npm-cache.tgz -C ~/.npm _cacache
```

内网机器恢复：

```bash
tar xzf npm-cache.tgz -C ~/.npm            # 展开缓存
npm ci --offline --no-audit --no-fund      # 完全离线安装
```

> 注意：`onnxruntime-node`、`@github/copilot-*`、Electron 等**带 postinstall
> 脚本**的包会向公网拉取原生二进制，离线 `npm ci` 时建议先
> `npm ci --ignore-scripts` 再按需手工补放二进制（见 3.1）。

### 3.1 原生依赖的手工补齐

| 包 | 需要的文件 | 获取方式 |
| --- | --- | --- |
| `electron` | `node_modules/electron/dist/` | 有网机 `node node_modules/electron/install.js` 后整目录拷贝；或设 `ELECTRON_MIRROR`/`electron_config_cache` |
| `onnxruntime-node` | `node_modules/onnxruntime-node/bin/napi-v6/<platform>/` | 有网机补跑 install 脚本后拷贝；无语音转写需求时可缺失（功能降级） |
| `@github/copilot-*` | 内置 CLI 二进制 | npm 包自带，无需外网 |

## 4. 编译与打包

```bash
# 类型检查 + 渲染进程/主进程构建（不改代码即可无脑执行）
npm run build

# 单元测试（建议每次发版前跑）
npm test

# 终端安装包（产物在 release/）
npm run dist                 # 当前平台
npm run dist:win:x64         # Windows x64 安装包
npm run dist:win:arm64       # Windows arm64
npm run dist:portable:mac    # macOS zip
```

> 打包内置了合规校验（`compliance:*`、
> `scripts/verify-packaged-compliance.mjs`），离线环境下如第三方通知
> 生成需要网络，需提前在有网机器完成 `npm run compliance:licenses` 一次，
> 仓库会缓存产物。

## 5. 自动化脚本

`deploy/scripts/build-offline.sh` 把上述步骤串成一条命令：

```bash
# 有网机器：收集依赖
./deploy/scripts/build-offline.sh fetch

# 内网机器：离线安装 + 编译 + 打包
./deploy/scripts/build-offline.sh build --offline
./deploy/scripts/build-offline.sh dist  --platform win32
```

支持的环境变量：`NPM_REGISTRY`、`ELECTRON_MIRROR`、`HF_ENDPOINT`、
`SKILL_RECORDER_*`（构建期仅影响产物内的 doctor 默认值提示）。

## 6. 终端分发清单

| 事项 | 内容 |
| --- | --- |
| 安装包 | `release/` 下的 nsis/dmg/zip |
| 模型端点配置 | `llm.config.json` 推送到每台终端的 `~/.skill-recorder/`，或组策略设置环境变量 |
| 语音模型（可选） | 预置 `SKILL_RECORDER_MODELS_DIR` 指向公共目录，避免终端各自下载 |
| 首次自检 | 打开应用 → 运行内置 doctor，应显示 `私有 LLM · <端点> · <模型>` |

## 7. 常见问题

- **`npm ci` 卡在 postinstall**：一律 `npm ci --offline --ignore-scripts`，
  再按 3.1 手工补齐。
- **Electron 版本与 lockfile 不符报 HASH 错**：内网镜像里的 Electron 版本
  必须与 `package.json` 一致——镜像仓库请整版本目录同步。
- **dist 卡在 nsis 下载**：设置 `ELECTRON_BUILDER_BINARIES_MIRROR`。
- **首次运行 whisper 模型下载失败**：把模型目录从有网机器拷到
  `SKILL_RECORDER_MODELS_DIR`（默认 `~/.cache/skill-recorder/models`，
  具体以应用内提示为准），或设置 `HF_ENDPOINT` 指向内网镜像。
